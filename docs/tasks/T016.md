# T016 — FastAPI application and router registration (`main.py`)

**Task**: Create the FastAPI application and router registration in `backend/app/main.py`.

## What problem is this solving?

T011 through T015 built parts with nothing holding them: a database engine, a Redis pool, an exception
vocabulary, error handlers, a pagination envelope. None of it is reachable, because there is no
*application*. This task creates it — the object uvicorn runs, that routes requests and shuts things
down cleanly.

Before this, `backend/app/main.py` was a zero-byte file.

## What's actually in the file

### `create_app()` and the module-level `app`

Both exist, and the pair is deliberate.

`quickstart.md` documents starting the server with `uvicorn app.main:app`. That syntax means "import
the module `app.main`, find the attribute `app`" — so a module-level `app` object has to exist under
exactly that name. Renaming it breaks the documented way to run the project.

But building the application inline at module level would mean there is only ever *one*, shared by
every test. A test that adds a route to check something would leave that route attached for every test
that follows. So the assembly lives in `create_app()`, a factory returning a fresh instance, and the
module-level `app` is just one call to it. Tests build their own; uvicorn gets the shared one. There's
a test asserting two calls return different objects.

### `lifespan` — and why startup does nothing

FastAPI's `lifespan` is an async context manager wrapping the server's whole serving lifetime:
everything before the `yield` runs at startup, everything after runs at shutdown.

**Before the `yield`: nothing.** This is a real decision, not an omission. Both pools — the SQLAlchemy
engine and the Redis client — connect *lazily*, on first use. It would be easy to "verify
connectivity" at startup by pinging both. The reason not to is that it converts a brief dependency
blip into a server that refuses to start at all. If Redis is restarting, an eager check means no
requests get served, including the many that never touch Redis. Lazy connection means those requests
succeed and only the ones actually needing Redis fail — with the `DegradedError` envelope from T013,
which is the behaviour FR-049 asks for.

**After the `yield`: close both pools.** `dispose_engine()` then `close_redis()`, so the process
doesn't exit leaving connections open on PostgreSQL and Redis.

### `register_routers()` — an empty function on purpose

Each of the six modules will own exactly one router, attached here as it is built. Right now the
function body is only a docstring, because **no module has a router yet** — the first arrives with the
audiences router in T058.

An empty function is better than no function: it names the place routers go, so the next person
doesn't have to decide, and it keeps `create_app()` reading as a list of assembly steps.

There is also **no health endpoint**, which is worth stating because adding one is the reflex. The API
contract is the single source of truth for the HTTP surface (Constitution III), and it doesn't list a
health check. Inventing one here would put an endpoint in the code that no document describes — the
exact drift the constitution's rule exists to prevent. If a health check turns out to be wanted, it
gets contracted first. A test pins this: the only paths on a fresh app are FastAPI's own documentation
routes.

### What this task deliberately leaves out

**The bind guard.** FR-078 requires the server to bind to loopback unless an explicit flag allows
otherwise, and `tasks.md` places that in `main.py` too — but as **T017/T018**, with T017 writing the
failing tests first. Implementing it here would have skipped the test-first step Constitution IV
requires. T018 will edit this file.

## Tests

`backend/tests/unit/test_app.py` — seven tests, none opening a connection:

- the module exposes `app` for uvicorn (pinning the name `quickstart.md` depends on)
- each `create_app()` call builds an independent application
- the application is named and versioned
- error handling is installed — proven *by behaviour*, raising a `NotFoundError` through a probe route
  and asserting the shared envelope comes back, rather than inspecting the handler registry
- no endpoints are exposed yet, beyond FastAPI's own docs routes
- startup connects to nothing
- shutdown closes both pools, in order

The last two drive the lifespan directly via `built.router.lifespan_context(built)`, with
`dispose_engine` and `close_redis` swapped for recording stand-ins. That's how shutdown gets verified
without a live PostgreSQL or Redis, which Constitution IV forbids a test from touching.

Coverage of `app/main.py` is 100%. The whole suite is 77 tests, every module at 100%.

## Live verification

Booted the real server the way `quickstart.md` says to:

```text
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8137
INFO:     127.0.0.1 - "GET /openapi.json HTTP/1.1" 200 OK
INFO:     127.0.0.1 - "GET /audiences HTTP/1.1" 404 Not Found
INFO:     Application shutdown complete.
```

And the 404 body came back as the shared envelope rather than Starlette's plain text:

```json
{"error": {"code": "not_found", "message": "Not Found", "details": {}}}
```

Three things confirmed at once: the app starts under uvicorn, T014's handlers are genuinely wired into
a running server (not just a `TestClient`), and shutdown completes cleanly with both pool-closing
calls running without error.

`/audiences` returning 404 is correct today — the route doesn't exist until T058.
