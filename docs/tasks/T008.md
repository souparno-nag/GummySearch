# T008 — `.env.example`

**Task**: Create `.env.example` documenting Reddit credentials, provider credentials, the pinned
model identifier, and the exposure flag.

## What problem is this solving?

`.env` (the real file with real secrets) is gitignored, which is correct — but it means anyone who
clones this repo fresh has *no idea* what environment variables the app actually needs, or what they
should look like. `.env.example` solves that: it's a template with the same variable names as `.env`,
but with blank or safe placeholder values instead of real secrets. It's meant to be committed to git
and copied (`cp .env.example .env`) as the starting point for a real local setup.

## What's in it

Every variable `backend/app/config.py` (T007) reads, grouped with a comment explaining each:

- **Reddit credentials** — with a pointer to where you actually get them
  (`reddit.com/prefs/apps`), since a blank `REDDIT_CLIENT_ID=` alone doesn't tell a new contributor
  where to go.
- **`DATABASE_URL`** — pre-filled with the same value that matches `docker-compose.yml`'s default
  local Postgres credentials, so someone following the standard local setup doesn't need to invent
  a connection string themselves.
- **`REDIS_URL`** — same idea, pre-filled with the local default.
- **`GROQ_API_KEY` / `GROQ_MODEL`** — left blank, with an explicit warning not to leave a "latest"
  or generic alias in `GROQ_MODEL`. This connects back to a constitution rule (Principle VII): the
  exact model version being used must always be pinned and recorded, so that if something changes
  later, you can tell whether it was *your* prompt change or the *provider* silently swapping the
  model underneath a floating name like "latest".
- **`EMBEDDING_MODEL_NAME`** — pre-filled with the real local embedding model chosen earlier
  (`sentence-transformers/all-MiniLM-L6-v2`), with a note that changing it later means every
  already-embedded piece of content needs to be re-embedded (different embedding models produce
  numbers that aren't comparable to each other).
- **`ALLOW_REMOTE_EXPOSURE`** — new. See below.

## The exposure flag — a piece of config that didn't exist yet

This task specifically calls out documenting "the exposure flag," which refers to a specification
requirement (FR-078): by default, this application must only be reachable from your own machine, and
making it reachable from the wider network must require a deliberate, explicit setting — never happen
by accident. The actual startup logic that *enforces* this (refusing to start if bound to a public
interface without permission) is a separate, later task, but since this task asked for the flag to be
documented now, it made sense to also add the setting itself to `config.py` at the same time, rather
than write documentation for a setting that doesn't exist yet as real, working config. So
`config.py` gained one more field: `allow_remote_exposure`, defaulting to `False`, read from
`ALLOW_REMOTE_EXPOSURE` in `.env`. When the actual startup guard is built later, it will simply check
`settings.allow_remote_exposure` — the wiring is already in place.
